# Development guide

This guide is for developers who want to understand, build, modify or contribute to MultiView. If you only want to run it, start with [Getting started](./getting-started.md) and [Configuration](./configuration.md).

## 1. Overview

MultiView is one Node.js process plus a single-page frontend.

```
Browser (Vue SPA)
   │  same origin
   ▼
Node process (Hono)
   ├─ /api/*          JSON API, answered from the cache and SQLite only
   ├─ /thumbnails/*   channel icons stored under data/thumbnails/
   └─ /*              built frontend + fallback to index.html
   │
   ├─ poller / refresher ──► YouTube Data API v3, Twitch Helix
   └─ SQLite (data/multiview.db)
```

- **One process.** The backend ([`server/`](../server)) is a [Hono](https://hono.dev/) app on `@hono/node-server`. It serves the API and the static frontend, so everything is on one origin and the server has no CORS setup.
- **SQLite.** All server state is in one better-sqlite3 database file and a folder of icon images next to it.
- **No login.** There are no user accounts. The only secret a client can present is the operator's `admin_token`. Per-user state (favorites, layouts, volumes, settings) lives in the browser's `localStorage`.
- **The API never fetches on demand.** `GET` endpoints return what is already cached. External APIs are called only by the code paths below.

| Caller | External service | When |
|---|---|---|
| Backend | YouTube Data API v3 (`playlistItems.list`, `videos.list`, `channels.list`) | Polling timers, manual refresh, icon backfill at start-up, admin channel refresh |
| Backend | Twitch (`id.twitch.tv/oauth2/token`, Helix `streams` and `users`) | Same as above |
| Backend | Icon image URLs returned by those APIs | When a channel icon is downloaded |
| Browser | YouTube and Twitch embedded players and chat iframes | On the multiview page |
| Browser | YouTube oEmbed (`youtube.com/oembed`) | To get the title and channel of a video added by URL or restored from a shared layout |
| Browser | `i.ytimg.com` and Twitch preview images | Video thumbnails (the API returns absolute URLs) |
| Browser | Google Fonts | `index.html` loads the Roboto font |

## 3. Prerequisites

- **Node.js 24.** The [Dockerfile](../Dockerfile) pins an exact version (`NODE_VERSION`, currently 24.21.0) instead of a floating tag, and it is bumped deliberately. The background: Node 24.19 to 24.21 abort intermittently in native addons built on `node::ObjectWrap` (`nodejs/node#65446`). better-sqlite3 has used Node-API since 13.0 and is not affected, but check this before adding another native addon. better-sqlite3 itself requires Node 22 or later.
- **npm.** Both packages have a `package-lock.json`. The backend and the frontend are separate packages with separate `node_modules`.
- **No compiler.** better-sqlite3 is a native addon, but its package ships prebuilt binaries for Windows, macOS and Linux (glibc and musl) on x64 and arm64. [`server/.npmrc`](../server/.npmrc) sets `ignore-scripts=true`; without it, installing from the lockfile makes npm run `node-gyp rebuild` for the package, which needs a toolchain and only rebuilds what is already there.
- **API credentials.** A YouTube Data API v3 key and a Twitch application's client ID and secret. [Getting started](./getting-started.md) explains how to obtain them. A credential is only used when a channel of that platform is configured (see [Failure behaviour](#failure-behaviour)).

## 4. Local development

Create the config first:

```bash
cp config/config.yaml.example config/config.yaml
# edit config/config.yaml
```

### Backend

```bash
cd server
npm install
npm run dev        # http://localhost:3000
```

| Script | Command | Purpose |
|---|---|---|
| `npm run dev` | `tsx watch src/index.ts` | Run the TypeScript sources directly and restart on change |
| `npm run build` | `tsc` | Compile to `server/dist/` |
| `npm start` | `node dist/index.js` | Run the compiled output |
| `npm run typecheck` | `tsc --noEmit -p tsconfig.test.json` | Type check the sources and the tests |
| `npm test` | `node --import tsx --test "test/**/*.test.ts"` | Run the unit tests |

Default paths are relative to the working directory. Started from `server/`, the process reads `../config/config.yaml`, writes `../data/multiview.db`, and looks for the frontend in `server/public`. A fresh checkout has no such folder, so the server runs API-only and answers non-API paths with a short text message.

Every restart runs the full start-up sequence. A target whose last successful fetch is younger than its polling interval is not fetched again, so watch-mode restarts do not burn quota. To develop without background polling, set `polling_enabled: false`; the only automatic calls left are the icon lookups for channels that have no stored icon yet.

### Tests

```bash
cd server
npm test
```

The tests in [`server/test/`](../server/test) use Node's built-in test runner and run the TypeScript sources through `tsx`. They need no API credentials and no network access: the global `fetch` is replaced with a stub that plays the part of YouTube and Twitch, and each test file works on a scratch database in the system's temp directory. They cover config validation, admin authentication, quota accounting, the YouTube fetch cycle, and the lookup of channel names and icons.

The frontend has no automated tests.

### Frontend

```bash
cd frontend
npm install
npm run serve      # Vite dev server on http://localhost:8080
```

| Script | Command | Purpose |
|---|---|---|
| `npm run serve` | `vite` | Dev server with hot reload, port 8080 |
| `npm run build` | `vite build --mode prod` | Production build to `frontend/dist/` |
| `npm run preview` | `vite preview` | Serve the production build |

The frontend always calls `${window.location.origin}/api` ([`utils/backend-api.ts`](../frontend/src/utils/backend-api.ts)). In development the Vite proxy forwards `/api` to the backend. Two variables, read from the process environment or from a `.env` file in `frontend/`, control the proxy:

| Variable | Default | Effect |
|---|---|---|
| `API_BASE_URL` | `http://localhost:3000` | Proxy target |
| `REWRITE_API_ROUTES` | unset | When set, the `/api` prefix is stripped before forwarding |

`/thumbnails` is proxied to the same target, so channel icons load on the Vite dev server too.

### Environment variables read by the server

| Variable | Default | Value in the Docker image | Purpose |
|---|---|---|---|
| `CONFIG_PATH` | `<cwd>/../config/config.yaml` | `/app/config/config.yaml` | Path of the config file |
| `DB_PATH` | `<cwd>/../data/multiview.db` | `/app/data/multiview.db` | SQLite file. Its directory is created if missing. Icons go to a `thumbnails/` folder next to it. |

```bash
cd frontend && npm run build
cd ../server && PUBLIC_DIR=../frontend/dist npm run dev
```

The backend then serves the built frontend, the API and the icons on port 3000. The second line uses POSIX shell syntax to set the variable; set `PUBLIC_DIR` the way your shell requires.

## 5. Backend internals

### Start-up sequence

[`index.ts`](../server/src/index.ts) runs these steps in order:

1. Load and validate `config.yaml`. On failure, print `[startup] failed: <reason>` and exit with code 1.
2. Open the database, create missing tables, add missing columns.
3. Store the config in [`state.ts`](../server/src/state.ts) and create the quota counter.
4. Sync the `channels` table with the config.
5. Register the fetch functions for the three refresh targets and the channel refresher.
6. Start the icon backfill in the background (not awaited; a failure is logged and does not stop start-up).
7. Build the Hono app.
8. Start the poller. It does nothing when `polling_enabled` is `false`.
9. Listen on `PORT`.

`SIGINT` and `SIGTERM` stop the timers, close the database and exit.

### Configuration

[`config.ts`](../server/src/config.ts) reads the file once at start-up. There is no reload; a change needs a restart.

| Key | Validation | Default |
|---|---|---|
| `youtube_api_key`, `twitch_client_id`, `twitch_client_secret`, `admin_token` | Required, non-empty string | none |
| `site_name` | String | `""` |
| `site_links` | Array of `{ label, url, icon? }`; `label` and `url` required | `[]` |
| `polling_enabled`, `public_refresh_enabled` | Boolean | `true`, `false` |
| `poll_interval_live_youtube_minutes`, `poll_interval_live_twitch_minutes`, `poll_interval_archive_minutes` | Finite number | `3`, `1`, `15` |
| `youtube_quota_limit`, `quota_safety_margin` | Finite number | `10000`, `0.95` |
| `channels.youtube[]` | `id` and `name` non-empty strings; `live` and `video` required booleans | `[]` |
| `channels.twitch[]` | `id` and `name` non-empty strings | `[]` |

A missing file, invalid YAML, a missing required key or a value of the wrong type raises `ConfigError` and stops start-up. The three polling intervals must be greater than 0; other numbers are not range-checked. Unknown keys are ignored. `channels` itself may be omitted; the server then starts with no channels.

Two things about the keys are easy to get wrong:

- A channel's `name` is only stored in the database. Clients are always sent the name fetched from the platform (`display_name`), never the configured one.
- Nothing about the site's own domain is configured. Twitch embeds take their `parent` from `window.location.hostname`.

### Database

[`db.ts`](../server/src/db.ts) opens the file in WAL mode with foreign keys on. Tables are created with `IF NOT EXISTS`, and `migrate()` adds columns that an older database lacks.

| Table | Purpose | Columns |
|---|---|---|
| `channels` | One row per configured channel | `id` (primary key: YouTube channel ID or Twitch login), `platform`, `name` (from config), `display_name`, `handle` (YouTube handle without `@`), `thumbnail` (relative URL of the stored icon), `live`, `video` (0/1; always 1 for Twitch) |
| `archive_videos` | Accumulated YouTube videos. Rows are removed only when their channel leaves the config. | `id` (primary key: video ID), `channel_id` (references `channels.id`), `title`, `published_at`, `start_actual`, `end_actual`, `duration` (seconds), `fetched_at`; indexes on `channel_id` and `published_at` |
| `quota_usage` | Estimated YouTube units, one row per day. Old rows are not deleted. | `date` (primary key: `YYYY-MM-DD` in Pacific Time), `used` |
| `kv` | Small state that must survive restarts | `key` (primary key), `value` |

Keys in `kv`:

| Key | Value |
|---|---|
| `live_cache_youtube`, `live_cache_twitch` | JSON array of the last fetched live/upcoming items |
| `last_updated:live_youtube`, `last_updated:live_twitch`, `last_updated:archive` | ISO 8601 time of the last successful fetch |

The channel sync in [`services/channels.ts`](../server/src/services/channels.ts) runs in one transaction. It upserts every configured channel, overwriting `platform`, `name`, `live` and `video` and keeping `display_name`, `handle` and `thumbnail`. Channels that are no longer in the config are deleted together with their archive rows.

### Cache and persistence

| State | In memory | Persisted | After a restart |
|---|---|---|---|
| Live/upcoming items, per platform | [`cache.ts`](../server/src/cache.ts) | `kv` | Restored on first access |
| `last_updated` per target | [`refresher.ts`](../server/src/refresher.ts) | `kv` | Restored on first access |
| `status`, `started_at`, `last_error` per target | `refresher.ts` | no | Reset to idle |
| Archives | no | `archive_videos` | Kept |
| Quota used today | no | `quota_usage` | Kept |
| `last_call_at` of the quota state | [`quota.ts`](../server/src/quota.ts) | no | `null` until the next YouTube call |
| Twitch app access token | [`services/twitch.ts`](../server/src/services/twitch.ts) | no | Requested again when needed |

The YouTube and Twitch halves of the live cache are separate. `getLive()` concatenates them, so a failed YouTube refresh leaves the previous YouTube items in place while Twitch keeps updating.

### Refresh targets and the refresher

There are three internal targets, each with its own fetch function ([`services/fetchers.ts`](../server/src/services/fetchers.ts)):

| Target | Fetches | Channels used | Stores to |
|---|---|---|---|
| `live_youtube` | YouTube live and upcoming streams | YouTube channels with `live: true` | YouTube half of the live cache |
| `live_twitch` | Twitch live streams | All Twitch channels | Twitch half of the live cache |
| `archive` | YouTube videos that are not live or upcoming | YouTube channels with `video: true` | `archive_videos` (upsert) |

The API exposes `live` (both live targets), `archive` and `all`. For `live`, the reported status is `running` if either half is running, `last_updated` is the later of the two, and `last_error` joins both errors with `; `.

`refresher.start(target)` is the only way a fetch runs:

- If a job for the target is already running, its promise is returned and no second fetch starts.
- Otherwise the job starts. On success `last_updated` is set and persisted and `last_error` is cleared. On failure `last_error` holds the message, which is also logged. There is no retry other than the next trigger.

### Polling

[`poller.ts`](../server/src/poller.ts) runs only when `polling_enabled` is `true`.

- Each target has its own `setInterval`, using its configured interval.
- At start-up, a target is fetched immediately unless its persisted `last_updated` is younger than its interval. In that case only the timer is armed.
- Whenever a new job starts for a target, including one started by a manual refresh, that target's timer is re-armed. The next poll is therefore one full interval after the latest fetch.

With `polling_enabled: false` no list is fetched automatically. The lists show whatever the database holds from earlier refreshes. The icon backfill at start-up runs in both modes.

### Manual refresh

`POST /api/refresh` and `POST /api/admin/refresh` call `refresher.start()` for the requested targets and return `202` at once. The client polls `GET /api/refresh/status` until the target is `idle`, then reloads the list. The home page does this every 2 seconds for at most 60 seconds, and shows `last_error` if one is set.

Jobs are shared only while one is running. Once a job has finished, the next request starts a new one; there is no cooldown. With `public_refresh_enabled: true`, every visitor can therefore trigger YouTube calls.

### YouTube fetching and quota accounting

[`services/youtube.ts`](../server/src/services/youtube.ts) makes three kinds of calls. `search.list` is not used. The costs come from `QUOTA_COST` in [`quota.ts`](../server/src/quota.ts).

| Call | Purpose | One call covers | Units charged per call |
|---|---|---|---|
| `playlistItems.list` (`maxResults=10`) on the uploads playlist, whose ID is the channel ID with `UC` replaced by `UU` | The 10 most recent uploads of a channel | 1 channel | 1 |
| `videos.list` (`snippet,liveStreamingDetails,status,contentDetails`) | Details of those videos | up to 50 video IDs | 1 |
| `channels.list` (`snippet`) | Channel title, handle and icon URL | up to 50 channel IDs | 1 |

One cycle of `live_youtube` or `archive` calls `fetchYouTube()` with that target's channels:

1. One `playlistItems.list` call per channel.
2. `videos.list` calls for all collected IDs, 50 per call.
3. Each video is classified by `snippet.liveBroadcastContent`: `live` and `upcoming` are live items; `none` with `status.uploadStatus = processed` is an archive row. This includes ordinary uploads, not only finished streams.

The two targets run independently. Each keeps only its half of the result, so a channel with both flags is queried once per target.

With `L` channels that have `live: true` and `A` channels that have `video: true`:

```
live cycle     = L + ceil(V / 50)   where V = video IDs returned, at most 10 × L
               ≤ L + ceil(L / 5)
archive cycle  ≤ A + ceil(A / 5)

units per day  ≈ (1440 / poll_interval_live_youtube_minutes) × live cycle
               + (1440 / poll_interval_archive_minutes)      × archive cycle
               + manual refreshes + channel lookups
```

Example: 10 channels with both flags and the default intervals give 480 × 12 + 96 × 12 = 6,912 units per day.

Accounting rules:

- Before every call, `canSpend(cost)` checks `used + cost <= youtube_quota_limit × quota_safety_margin`. If not, the call is not made and `QuotaExceededError` is thrown.
- `spend(cost)` is recorded before the HTTP request, so a call that fails is still counted.
- The check is per call. A cycle that reaches the threshold part-way fails as a whole: its partial results are dropped and the previous cache is kept.
- The counter is keyed by the current date in `America/Los_Angeles`. A new day starts with no row, which is how the counter resets at midnight Pacific Time.
- The counter is this server's own estimate, stored in its own database. Nothing is read back from Google, and instances that share one API key count separately.
- `GET /api/quota` reports `exceeded` as `true` once not even a 1-unit call fits under `limit × margin`, that is, while YouTube calls are being refused. The settings page shows a notice in that state, and the refused jobs also appear as `last_error` in `/api/refresh/status`.

Channel lookups (`channels.list`) happen at start-up for YouTube channels without a stored icon, and for all YouTube channels on `POST /api/admin/channels/refresh`. Both cost `ceil(channels / 50)` units.

### Twitch

[`services/twitch.ts`](../server/src/services/twitch.ts) uses an app access token from the client credentials flow. The token is kept in memory and treated as expired 60 seconds early. A Helix call that returns `401` triggers one forced token renewal and one retry.

- `GET /helix/streams` with up to 100 `user_login` values per call returns the live streams. An item's `id` and `channel.id` are the lowercased login.
- `GET /helix/users` with up to 100 `login` values per call returns the icon URL and display name.

Twitch calls are not counted against any quota. Only live streams are fetched for Twitch; archives are YouTube only.

Twitch `id` values are lowercased when the config is loaded. Stream items are keyed by the lowercased login, and icons and names are written back to the row whose `id` equals the login that Helix returns, which is always lowercase.

### Channel names and icons

- **When.** At start-up, channels whose `thumbnail` is `NULL` are looked up (`fillMissingThumbnails`), YouTube and Twitch independently: a failure on one platform is reported but does not skip the other. `POST /api/admin/channels/refresh` looks up every channel. Nothing else refreshes names or icons, so a renamed channel is picked up only by the admin call.
- **Icons.** [`services/thumbnails.ts`](../server/src/services/thumbnails.ts) downloads the image and writes it to `data/thumbnails/<id>.<hash>.<ext>`, where `<hash>` is the first 8 hex digits of the SHA-256 of the content. It writes to a temporary file and renames it, then deletes older files of the same channel. The database stores the relative URL `/thumbnails/<file>`.
- **Serving.** `/thumbnails/*` is served with `Cache-Control: public, max-age=31536000, immutable`. A changed icon gets a new file name, so the long cache lifetime is safe. A request for a file that does not exist gets a `404` without that header.
- **Names.** `display_name` comes from the YouTube channel title or the Twitch display name. For a live Twitch stream whose channel has no `display_name` yet, the name from the stream is used.
- **Video thumbnails** are not stored. YouTube items get `https://i.ytimg.com/vi/<id>/hqdefault.jpg`; Twitch items get the stream preview URL at 640×360.

### Admin authentication

[`middleware/auth.ts`](../server/src/middleware/auth.ts) reads `Authorization: Bearer <token>` and compares the token with `admin_token` in constant time (`crypto.timingSafeEqual`).

| Middleware | Applied to | Behaviour |
|---|---|---|
| `requireAdmin` | Everything under `/api/admin/` | `401` without a bearer token, `403` when it does not match |
| `refreshGate` | `POST /api/refresh` | Passes everyone when `public_refresh_enabled` is `true`; otherwise `403` unless the token matches |

`admin_token` is never part of any response. The frontend has no place to enter it: the refresh button is shown only when `public_refresh_enabled` is `true`, and admin calls are made with a tool such as `curl`.

### Failure behaviour

| Situation | What happens |
|---|---|
| Config missing or invalid | The process exits with code 1 before listening |
| No channels of a platform configured | No request is ever sent to that platform; its credentials only need to be non-empty strings |
| Wrong YouTube key, YouTube channels configured | YouTube answers with an error status, so each YouTube job throws on its first call. `last_error` is set and logged, the job is retried at the next interval, and each attempt adds one unit to the local counter. Twitch is unaffected. |
| Wrong Twitch credentials, Twitch channels configured | The token request fails, so each `live_twitch` job fails and is retried at the next interval. YouTube is unaffected. |
| One YouTube channel's playlist call returns `404` (no public videos yet, a wrong ID, a removed channel) | That channel is skipped and logged once per process; the other channels are fetched normally |
| One YouTube channel's playlist call returns any other error | The whole cycle of that target fails |
| Quota threshold reached | YouTube jobs fail without calling the API, the previous YouTube items stay in the cache, Twitch continues |
| Icon backfill fails for one platform | The error is logged and the other platform is still processed; missing icons are tried again at the next start |

## 6. HTTP API reference

All routes are mounted in [`index.ts`](../server/src/index.ts). Any other path under `/api/` returns `404 { "error": "not found" }`. Errors are JSON objects of the form `{ "error": string }`.

| Method | Path | Auth | Parameters | Success response |
|---|---|---|---|---|
| `GET` | `/api/health` | none | none | `200 { "status": "ok" }` |
| `GET` | `/api/videos/live` | none | none | `200 { items, last_updated }` |
| `GET` | `/api/videos/archive` | none | none | `200 { items, last_updated }` |
| `GET` | `/api/channels` | none | none | `200 { channels }` |
| `GET` | `/api/config/public` | none | none | `200 { public_refresh_enabled, site_name, site_links }` |
| `GET` | `/api/quota` | none | none | `200 { date, used, limit, last_call_at, exceeded }` |
| `GET` | `/api/refresh/status` | none | none | `200 { live, archive }` |
| `POST` | `/api/refresh` | admin token unless `public_refresh_enabled` | query `target` | `202 { accepted: true, target }` |
| `POST` | `/api/admin/refresh` | admin token | query `target` | `202 { accepted: true, target }` |
| `POST` | `/api/admin/channels/refresh` | admin token | none | `200 { ok: true }` |

None of the `POST` routes read a request body.

### Videos

`GET /api/videos/live` returns the cached YouTube and Twitch items. `GET /api/videos/archive` returns the 200 most recently published rows of `archive_videos`. In both, `last_updated` is an ISO 8601 string or `null`.

| Item field | Type | Notes |
|---|---|---|
| `id` | string | YouTube video ID, or the lowercased Twitch login |
| `title` | string | |
| `type` | `"stream"` or `"video"` | `stream` for live and upcoming items, `video` for archive items |
| `status` | `"live"`, `"upcoming"` or `"past"` | |
| `published_at` | string | For Twitch, the stream start time |
| `available_at` | string | Added when the response is built: `start_actual`, else `start_scheduled`, else `published_at` |
| `start_scheduled` | string, optional | YouTube live and upcoming items |
| `start_actual` | string, optional | |
| `end_actual` | string, optional | Archive items |
| `duration` | number, optional | Seconds; archive items |
| `thumbnail` | string | Absolute URL |
| `channel` | `{ id, platform, name }` | `platform` is `"youtube"` or `"twitch"`. The icon is not included; clients look it up in `/api/channels`. |

Both responses send `Cache-Control: no-cache` and, once the target has been fetched at least once, an `ETag` derived from `last_updated`. A request whose `If-None-Match` equals it gets `304` with no body. The live `ETag` covers both the YouTube and the Twitch time, so it changes when either half is updated.

### Channels

`GET /api/channels` returns `{ channels: [...] }` with `Cache-Control: public, max-age=300`.

| Field | Type | Notes |
|---|---|---|
| `id` | string | |
| `platform` | `"youtube"` or `"twitch"` | |
| `name` | string | `display_name`; empty until it has been fetched |
| `handle` | string | YouTube handle without `@`; empty if unknown |
| `thumbnail` | string | `/thumbnails/<file>`; empty until it has been fetched |
| `live`, `video` | boolean | The config flags |

### Public config and quota

`GET /api/config/public` (`Cache-Control: public, max-age=300`) returns only the four fields listed above. `site_name` is `""` and `site_links` is `[]` when unset.

`GET /api/quota` (`Cache-Control: no-store`) returns the PT `date`, the `used` units, the configured `limit` (not multiplied by the margin), `last_call_at` and `exceeded`.

### Refresh

`target` is `live`, `archive` or `all`. It defaults to `all`. Any other value returns `400`.

| Route | Status codes |
|---|---|
| `POST /api/refresh` | `202` accepted; `400` bad target; `403` when refresh is not public and the token is missing or wrong |
| `POST /api/admin/refresh` | `202`; `400`; `401` no token; `403` wrong token |
| `POST /api/admin/channels/refresh` | `200` when done; `401`; `403`; `500` with the error message when a lookup fails |

The two refresh routes return before the fetch finishes. The channel refresh waits for completion and runs the YouTube lookup first, then the Twitch lookup.

`GET /api/refresh/status` (`Cache-Control: no-store`) returns one state object for `live` and one for `archive`:

| Field | Type | Notes |
|---|---|---|
| `status` | `"idle"` or `"running"` | |
| `last_updated` | string or `null` | Last successful fetch |
| `last_error` | string or `null` | Message of the last failed fetch; cleared by the next success |
| `started_at` | string or `null` | Start time of the running job |

### Non-API paths

| Path | Behaviour |
|---|---|
| `/thumbnails/*` | Channel icon files |
| `/*` | A file from `PUBLIC_DIR` if one matches; otherwise `index.html` for `GET` requests, which lets the client-side router handle the path |

## 7. Frontend internals

### Stack

Vue 3 with Options API components, Vuetify 3, Pinia with `pinia-plugin-persistedstate`, vue-router 4 in history mode, vue-i18n 11 in legacy mode, axios, dayjs and Vite 8. Vuetify components are resolved automatically by `unplugin-vue-components`; application components are imported by hand. Icons are SVG paths from `@mdi/js`. [`utils/icons.ts`](../frontend/src/utils/icons.ts) re-exports the commonly used ones and is exposed to every component as `this.icons`.

[`main.ts`](../frontend/src/main.ts) installs Pinia first, then creates the settings store and loads the user's locale before mounting. The order matters: the persistence plugin only applies to stores created after `app.use(pinia)`.

### Routes

Defined in [`router/index.ts`](../frontend/src/router/index.ts).

| Path | Name | View | Notes |
|---|---|---|---|
| `/` | `home` | `HomeFave.vue` | Live/upcoming and archive tabs. On the first navigation it redirects to the page chosen in settings (`defaultOpen`). |
| `/home` | | | Redirects to `home` |
| `/favorites/` | `favorites` | `HomeFave.vue` with `isFavPage` | Same lists, limited to favorite channels |
| `/multiview/:layout?` | `multiview` | `MultiView.vue` | Optional encoded layout |
| `/channels` | `channels` | `ChannelList.vue` | All channels, with favorite, hide and volume controls |
| `/search` | `search` | `Search.vue` | Filters the loaded lists by title or channel name, in the browser |
| `/settings` | `settings` | `Settings.vue` | Language, theme, quota display, export, import, reset |
| `/404` and unmatched | | `NotFound.vue` | |

All views except `HomeFave` are loaded lazily. [`App.vue`](../frontend/src/App.vue) renders the multiview route outside `keep-alive` and the others inside it.

### Stores

Stores are in [`frontend/src/store/`](../frontend/src/store). Persisted stores are written to `localStorage` as JSON under the key shown.

| Store | `localStorage` key | Persisted | Holds |
|---|---|---|---|
| `root` | `multiview-root-v1` | `firstVisit`, `showUpdateDetails`, `currentGridSize` | Shell state: mobile flag, drawer, page visibility, list density |
| `settings` | `multiview-settings-v1` | Everything except the four public config fields | Language, dark mode, default page, list view mode, hidden channels (`blockedChannels`), and a copy of the public config |
| `home` | none | nothing | `live`, `archive` and `channels` from the API, loading and error flags, fetch times |
| `favorites` | `multiview-favorites-v1` | `favorites` | Array of `{ id, name }` |
| `multiview` | `multiview-mv-v1` | `layout`, `layoutContent`, `presetLayout`, `autoLayout`, `ytUrlHistory`, `twUrlHistory`, `muteOthers`, `syncOffsets`, `snapIndex`, `titleFilter` | The grid, cell contents, custom presets and multiview options |
| `volume` | `multiview-volume-v1` | whole state | `volumes[key] = { volume, muted }`, keyed `youtube:<channelId>` or `twitch:<login>` |

Two more keys are used outside Pinia: `theme` (index of the selected color theme) and, as a read-only fallback, a legacy `darkMode` key.

[`store/index.ts`](../frontend/src/store/index.ts) also listens for `storage` events and patches the `root`, `settings`, `favorites` and `volume` stores when another tab changes them. The `multiview` store is left out on purpose, so each window keeps its own layout.

[`store/helpers.ts`](../frontend/src/store/helpers.ts) provides `mapState`, `mapGetters`, `mapActions` and `mapMutations` with a namespace string as first argument, which is how most components access stores.

The settings page exports a JSON file with `favorites`, the `settings` state, the `multiview` state and `volume`. Import applies favorites, volumes, custom presets (added by name), dark mode and language; other fields in the file are ignored.

### Talking to the backend

[`utils/backend-api.ts`](../frontend/src/utils/backend-api.ts) is the only API client: `live()`, `videos()`, `channels()`, `startRefresh()`, `refreshStatus()`, `publicConfig()` and `quota()`. Response types are in [`utils/types.ts`](../frontend/src/utils/types.ts).

The `home` store wraps the list calls and skips a request when the data is fresh enough (2 minutes for live, 10 for archive, 30 for channels by default). Live and archive requests are also skipped while the page is hidden, unless forced. `App.vue` loads the public config and the channel list once, and refreshes the live list on a 6-minute timer and when the tab becomes visible again.

Channel icons have a single source: `ChannelImg.vue` looks up the channel ID, or the YouTube handle, in the `home` store's channel list.

### Public config in the UI

`App.vue` calls `/api/config/public` on creation and stores the result with `settings.setPublicConfig()`. These fields are excluded from persistence, so they always reflect the server.

| Field | Used by |
|---|---|
| `publicRefreshEnabled` | `HomeFave.vue` shows the refresh button only when it is `true` |
| `siteName`, `siteLinks` | Footer of `NavDrawer.vue` and the About block of `Settings.vue`. A link's `icon` is resolved against the exports of `utils/icons.ts`; an unknown name gets a generic link icon. |

Views declare their page title with a `head()` option that builds it with [`utils/site.ts`](../frontend/src/utils/site.ts). `VueHeadMixin` from `@unhead/vue`, installed in `main.ts`, applies it, so the title follows the route, the UI language and `site_name`. The static `<title>` of [`index.html`](../frontend/index.html) is only the initial value.

### Multiview grid

Constants and encoding are in [`utils/mv-utils.ts`](../frontend/src/utils/mv-utils.ts); the page is [`views/MultiView.vue`](../frontend/src/views/MultiView.vue).

- **Coordinates.** The grid is 120 columns by 60 rows (`GRID_COLS`, `GRID_ROWS`) with a 1 px margin. Column width and row height are computed so that 120 × 60 fills the viewport below the toolbar. The row count is not capped: when no free spot is left, a new cell is placed below the existing ones.
- **Snap.** Dragging and resizing round to a step chosen from `SNAP_STEPS = [12, 10, 6, 5, 4, 3, 2, 1]`. The default is index 4, a step of 4 grid units. Coordinates themselves are always stored in 120 × 60 units.
- **Grid library.** `GridLayout` and `GridItem` come from the vendored copy in `src/external/vue-grid-layout`, which adds the `snapStep` prop. The grid runs with vertical compaction off and collision prevention on.
- **State.** `layout` is the array of cells (`x`, `y`, `w`, `h`, `i`). `layoutContent[i]` describes what a cell shows: `{ type: "video", id, video }` or `{ type: "chat", currentTab }`. A cell without content renders `EmptyCell`.
- **Cells.** `CellContainer` handles drag and drop of video cards and URLs, and wraps `VideoCell`, `ChatCell` or `EmptyCell`. Shared cell logic is in `CellMixin.ts`; layout changes are in `MultiviewLayoutMixin.ts`.
- **Presets.** `desktopPresets` (58) and `mobilePresets` (4) are encoded layout strings. A preset with `default: N` is the initial auto-layout for N videos. Custom presets are saved to `presetLayout`, and `autoLayout[N]` records the preferred preset per video count. Adding a video when no cell is free moves to the auto-layout for one more video, after a confirmation prompt if the current layout is not a preset.

Layout encoding, used by presets and shared URLs:

- Each of `x`, `y`, `w`, `h` is two characters from `A–Z a–z 0–9 - _` (value = first × 64 + second), so a cell starts with 8 characters.
- An optional suffix gives the content: `chat<N>` for a chat cell bound to video N, `twitch<login>` for a Twitch channel, or an 11-character YouTube video ID. N is zero-based and counts the video cells in decoded order, that is, sorted by x, then y.
- Cells are joined with commas. `AAAABsA8,BsAAAMA8chat0` is a 108 × 60 cell at the left and a 12 × 60 chat cell at x = 108.

The share menu in the toolbar builds `/multiview/<encoded layout>` with video IDs included. The archive sync bar can add `?t=<unix seconds>` and `&offsets=<comma-separated seconds>`. Opening such a URL decodes it in `mounted()`; if a layout already exists, `LayoutChangePrompt` asks before replacing it. Titles and channels of the decoded YouTube videos are then filled in through oEmbed.

### Players and chat

- [`YoutubePlayer.vue`](../frontend/src/components/player/YoutubePlayer.vue) wraps the `youtube-player` package.
- [`TwitchPlayer.vue`](../frontend/src/components/player/TwitchPlayer.vue) loads `https://player.twitch.tv/js/embed/v1.js` and creates `Twitch.Player` with `parent: [window.location.hostname]`.
- Both use `PlayerMixin.ts` for common props and state polling. Player objects are wrapped in `markRaw` so that Vue does not make them reactive.
- `VideoCell.vue` chooses the player by video type, restores the channel's saved volume and mute state when the player is ready, and writes changes back to the `volume` store.
- `MediaControls.vue` is the panel for volume, mute and playback of the video cells, one by one or all at once. `MultiviewSyncBar.vue` plays archived videos in sync, based on each video's `available_at` and `duration`.
- `ChatCell.vue` embeds `https://www.youtube.com/live_chat?v=<id>&embed_domain=<hostname>` or `https://www.twitch.tv/embed/<login>/chat?parent=<hostname>`. For an archived YouTube video it shows a notice instead.
- [`public/chat-popout.html`](../frontend/public/chat-popout.html) is a standalone page, opened with `window.open`, that shows the same chat embeds for the videos currently on the grid. It receives them through query parameters.

All of these embeds pass the page's own host name as `parent` or `embed_domain`. No configuration value is involved.

### Internationalisation

Setup is in [`plugins/vuetify.ts`](../frontend/src/plugins/vuetify.ts).

| Locale | Messages | Loading |
|---|---|---|
| `en` | [`locales/en/ui.yml`](../frontend/src/locales/en/ui.yml) | Bundled; also the fallback locale |
| `ja` | [`locales/ja-JP/ui.yml`](../frontend/src/locales/ja-JP/ui.yml) | Loaded on demand through `asyncLang` |

YAML files are imported with `@rollup/plugin-yaml`. The initial locale is derived from `navigator.language` and persisted in the settings store; a `?lang=` query parameter overrides it.

To add a locale:

1. Create `src/locales/<folder>/ui.yml` with the same keys as the English file.
2. Add `{ val, display }` to `langs`.
3. Add a loader with the same key to `asyncLang`. It imports the dayjs locale and returns the YAML module.

Vuetify's own messages are taken from the export of `vuetify/locale` with the same key, with English as fallback. The dayjs locale name is assumed to equal the key unless it is mapped in `dayjsName`.

### Relation to Holodex

The frontend is derived from the Holodex frontend; its license is kept in [`frontend/LICENSE-Holodex`](../frontend/LICENSE-Holodex).

- **Carried over:** the multiview page with its cells, presets, layout sharing, media controls and archive sync bar; the video card and list components; the navigation shell; the settings page; the player wrappers.
- **Specific to MultiView:** the API client and the `home` store (own backend), local-only favorites, the `volume` store, the channel list page, the chat pop-out page, site name and links.
- **Not present:** the router defines only the pages listed above. There is no login, watch page, per-channel page, playlist or translation feature.

Some leftovers remain: the `liveTl*` fields in the settings store and the `keep-alive` exclude list in `App.vue`.

## 8. Build and Docker

The [Dockerfile](../Dockerfile) has three stages, all on the same pinned `node:<NODE_VERSION>-alpine` image.

| Stage | What it does |
|---|---|
| `frontend-builder` | `npm ci` and `npm run build` in `frontend/`, producing `dist/`. It runs on the build machine's platform (`--platform=$BUILDPLATFORM`) because the output is static files. |
| `backend-builder` | `npm ci` and `npm run build` (`tsc`) in `server/`, then `npm prune --omit=dev` and removal of the SQLite binaries for platforms other than Alpine. Nothing is compiled, so this stage also runs on the build machine's platform. |
| runtime | Copies the backend's `dist/`, `node_modules/` and `package.json`, and the frontend's `dist/`. It runs no commands; the mount points are created with `WORKDIR`. |

Layout inside the image, with `/app` as working directory:

```
/app
├── server/dist/           compiled backend (entry: server/dist/index.js)
├── server/node_modules/   production dependencies, including the prebuilt better-sqlite3 binaries
├── server/package.json
├── public/                built frontend            (PUBLIC_DIR=./public)
├── config/                mount point; config.yaml  (CONFIG_PATH=/app/config/config.yaml)
└── data/                  mount point; multiview.db and thumbnails/  (DB_PATH=/app/data/multiview.db)
```

The container exposes port 3000 and starts with `node server/dist/index.js`.

**Health check.** Every 30 seconds (5-second timeout, 10-second start period, 3 retries) the image runs `wget` against `http://127.0.0.1:3000/api/health`. The port is fixed in the check, so changing `PORT` inside the container makes it fail; remap the host port instead.

**Compose files.** [`docker-compose.yml`](../docker-compose.yml) runs the published image and mounts `./config` and `./data`. To build from the working tree instead:

```bash
docker compose -f docker-compose.yml -f docker-compose.build.yml up --build
```

The frontend build writes source maps (`build.sourcemap: true`), which end up in `public/`. It also writes a bundle report to `frontend/stats.html`, which git ignores.

## 9. Conventions

- **Language.** Code comments, documentation and commit messages are written in English.
- **Backend.** TypeScript in strict mode, with `noUnusedLocals` and `noUnusedParameters`. The package is an ES module (`"type": "module"`) compiled with `module: NodeNext`, so relative imports carry the `.js` extension (`import { getDb } from "./db.js"`). Two-space indentation, double quotes, semicolons.
- **Frontend.** Vue single-file components in Options API style, mostly with `<script lang="ts">`. `@` is an alias for `frontend/src`. Mostly four-space indentation in scripts, double quotes, semicolons. The TypeScript config is not strict.
- **Checks.** In `server/`, `npm run typecheck` type-checks the sources and the tests, and `npm test` runs the unit tests. Run both before committing a backend change. The frontend has no lint, type-check or test script, and its build does not type-check.
- **Line endings.** [`.gitattributes`](../.gitattributes) forces LF on all platforms.
- **Vendored code.** `frontend/src/external/` holds third-party sources with their own license files. The `vue-grid-layout` copy has local changes: the `snapStep` prop and a `mitt` event bus.

## 10. Release process

A release is cut by pushing a version tag. The [Publish Docker image](../.github/workflows/docker-publish.yml) workflow then builds the image for `linux/amd64` and `linux/arm64` and pushes it to GitHub Container Registry as `ghcr.io/acc-off/multiview`.

1. Check that `main` builds. Run the workflow by hand from the repository's Actions tab ("Run workflow"): a manual run builds both platforms without publishing anything.
2. Set the new `version` in `server/package.json` and `frontend/package.json`, and commit.
3. Tag the commit and push the tag:

   ```bash
   git tag v1.2.3
   git push origin v1.2.3
   ```

4. Wait for the workflow to finish. It publishes the tags `1.2.3`, `1.2`, `1` and `latest`.
5. Write the release notes on GitHub (Releases → Draft a new release → choose the tag).

Tags must have the form `v<major>.<minor>.<patch>`. A pre-release tag such as `v1.3.0-rc.1` publishes only `1.3.0-rc.1` and leaves `1.3`, `1` and `latest` where they are.

Both variants are built on an `amd64` runner without emulation: the two build stages run on the runner's own platform, and the runtime stage only copies files. Keep it that way when changing the Dockerfile; a `RUN` in the runtime stage would need QEMU for the `arm64` variant.

To move to a newer Node release, change `NODE_VERSION` in the Dockerfile and run the workflow by hand before tagging.

The package's visibility is separate from the repository's. After the very first publish, check the package under the repository's Packages and make it public if it is not; users cannot pull it otherwise.
